Topic 01: What is Node.js?
Definition:

Node.js is a JavaScript Runtime Environment that allows developers to execute JavaScript code outside the browser on the server-side.

Topic 02: process & process.argv
What is process?

process is a global object providing information about and control over the current running Node.js process.

process.argv (Command Line Arguments):

An array holding all arguments passed via the terminal when launching the Node.js application:

$ node app.js Shivam 22
IndexValueDescription
argv[0]Path to Node.exeAbsolute filesystem path to Node executable
argv[1]Path to app.jsPath to the script file being executed
argv[2]"Shivam"First custom user command-line argument
argv[3]"22"Second custom user argument
Topic 03: module.exports & require()
  • require() ➔ Built-in CommonJS function used to import external modules and files.
  • module.exports ➔ Special object used to expose functions, objects, or variables to other files.
math.js: module.exports = sum;
➔ require('./math') ➔
app.js: const sum = require(...)
Requiring a Directory (Folder):

When importing an entire directory: const fruits = require('./fruits'); Node.js automatically searches for and executes the index.js file inside that folder!

💡
Key Takeaway: Just like main() is the entry point in languages like Java, index.js serves as the default entry point for folder imports in Node.js!
Topic 04: NPM (Node Package Manager)

NPM is the standard package manager for Node.js, fulfilling two core roles:

1. Online Registry (Open-source package library)
2. CLI Tool (Terminal package management)
$ npm install <package_name> # e.g. npm i express
Topic 05: Package Files & Folders
File / DirectoryDescription & Purpose
node_modules/ Directory storing all downloaded packages and transitive sub-dependencies (added to .gitignore due to large size).
package.json Holds project metadata (project name, version, start scripts, list of direct dependencies). Generated via npm init -y.
package-lock.json Locks and records the exact version of every installed dependency and nested sub-dependency for reproducible builds.
Topic 06: Local vs Global Packages
  • Local Installation: npm i <package> ➔ Installed inside the local project's node_modules.
  • Global Installation: npm i -g <package> ➔ Available system-wide as CLI utilities (e.g. nodemon).
  • npm link: Links a globally installed package to the local project without re-downloading.
