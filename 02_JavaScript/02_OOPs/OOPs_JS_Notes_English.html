Core Purpose of OOP:

Object-Oriented Programming models real-world business domains into modular, reusable objects bundling State (Properties) and Behavior (Methods) together, eliminating code redundancy (DRY principle).

Object Prototypes & Prototype Chaining:

Topic 02: Factory Functions vs Constructors & new
Factory Functions (Limitation: Memory Waste):

A plain function returning an object. Every instance copies functions into memory separately!

Constructor Functions & The 'new' Operator:

Constructors serve as blueprints. The new keyword performs 4 critical steps:

  • 1. Creates a brand new empty object {}.
  • 2. Binds this to that newly created object.
  • 3. Sets new object's __proto__ to Constructor.prototype.
  • 4. Automatically returns this.

Topic 04: Static Methods & Static Properties
Class-Level vs Instance-Level Members:

Members declared with static belong to the class itself, NOT to instance objects. They cannot be accessed via this from an instance.

  • Use Case: Utility helper functions (e.g. Math.max()), factory constructors, database connection singletons.

Topic 06: Pillar 1 — Encapsulation
Definition & Purpose:

Encapsulation is bundling state and methods inside an object while restricting direct external access to internal implementation details. It prevents accidental mutation and enforces a clean public API.

Topic 07: Pillar 2 — Inheritance
Definition & Subclassing:

Inheritance allows a child class to inherit attributes and methods from a parent class via extends, promoting code reuse.

  • super() ➔ Calls the parent class constructor (MUST be called before accessing this).
  • super.method() ➔ Calls parent class implementation directly.

Topic 08: Pillar 3 — Polymorphism
Definition (Many Forms):

Polymorphism allows different child classes to define their own custom implementations of a method that shares the same name in the parent class (Method Overriding).

Dynamic Dispatch & Duck Typing:

In JavaScript, polymorphism is dynamic: if different objects share a method signature, a loop can execute them uniformly without knowing the exact concrete type.

Topic 09: Pillar 4 — Abstraction
Definition: Hiding Implementation Complexity:

Abstraction hides the complex background mechanics and reveals only essential, intuitive interfaces to the user (e.g. you drive a car using pedals without knowing internal combustion physics).

Topic 11: Composition vs Inheritance
Architectural Principle:

"Favor object composition over class inheritance."

  • Inheritance ("Is-a"): Dog is an Animal. Rigid hierarchy; changes in base class can break all subclasses.
  • Composition ("Has-a"): Robot has a Flyer and Cleaner. Flexible; bundles independent functional abilities together.
